\section{Introduction}

This report evaluates a one-way Ku-band geostationary satellite link from Rome to Ankara. The analysis begins with a conventional clear-sky link budget and then adds interference, atmospheric attenuation, receiver-noise variation, apparent GEO motion, and DVB-S2 adaptive coding and modulation.

\subsection{System Architecture and Ku-Band Principles}
A circular equatorial orbit at an altitude of approximately 35,786~km has a period close to one sidereal day. A controlled spacecraft in this orbit therefore remains near a fixed longitude as viewed from the ground, allowing fixed parabolic antennas to be used. The corresponding slant range is about 37,000--38,000~km for the sites considered here, which produces more than 200~dB of free-space path loss. Small station-keeping excursions are evaluated separately to determine whether they have a measurable effect on this link.

The payload is modeled as a transparent \textit{bent-pipe} transponder. It filters, frequency-translates, amplifies, and retransmits the received uplink without demodulating the waveform on board.

Because the uplink waveform is not regenerated, uplink noise and interference are relayed with the wanted carrier. The uplink and downlink contributions must therefore be combined to obtain the end-to-end $(C/N_0)_{\text{total}}$.

The selected frequencies are 14.0~GHz for the uplink and 12.0~GHz for the downlink. A vertical linear-polarization case is used in the rain model, so ITU-R P.838-3 is evaluated with $\tau = 90^\circ$; a horizontal assignment would require $\tau = 0^\circ$. Ku-band permits useful antenna gain with relatively small apertures, but rain scattering and absorption are significant enough to require an explicit availability analysis.

\subsubsection{Satellite Selection Rationale}
HOTBIRD 13G was selected for this specific Rome--Ankara broadcast case, not as a general ranking of GEO satellites. Its $13^\circ$E orbital position gives similar elevation angles at the two terminals, and Eutelsat publishes a Ku-band widebeam EIRP map that can be used for a traceable report-level estimate \cite{eutelsat}. ``Intelsat'' denotes an operator fleet rather than one design point. A complete alternative would have to identify the spacecraft, orbital slot, beam, polarization, EIRP contour, transponder plan, and receive G/T. Intelsat 39 at $62^\circ$E has suitable regional Ku-band capacity \cite{intelsat39,ses_fleet_map}, but the Rome elevation is $20.8^\circ$, compared with $41.6^\circ$ for HOTBIRD 13G. The lower elevation increases both slant range and atmospheric path length on the uplink. For the service and sites defined in this report, HOTBIRD 13G therefore provides the more balanced and better-documented baseline.

\begin{itemize}
    \item \textbf{GS1 Rome:} The uplink site is at $41.9028^\circ$ N, $12.4964^\circ$ E. The antenna model uses a 2.4~m aperture, consistent with the Andrew Type 243 datasheet, which specifies 48.9~dBi gain at 14.3~GHz \cite{skyware_24m}. The transmitter is represented by the Norsat ATOMBKU020; its datasheet specifies $P_{\mathrm{1dB}} \ge 43$~dBm and a standard 14.0--14.5~GHz transmit range \cite{norsat_atombku}. The link budget uses 20~W as the nominal amplifier output.
    \item \textbf{HOTBIRD 13G:} The spacecraft is modeled at $13.0^\circ$E. Eutelsat's published widebeam map contains 40--53~dBW contours; the Ankara downlink is assigned \satEIRP~dBW as a conservative contour-based estimate \cite{eutelsat}. The selected transponder receive G/T is not published in the available operator material, so \satGT~dB/K remains an explicit engineering assumption.
    \item \textbf{GS2 Ankara:} The receive site is at $39.9334^\circ$ N, $32.8597^\circ$ E and 0.94~km altitude. The Triax TD88 sheet specifies a 95~cm by 85~cm offset reflector and 38.8~dBi gain at 11.7~GHz \cite{triax_td88}. The calculation represents this aperture by an equivalent 0.9~m circular dish and obtains approximately 39.0~dBi at 12~GHz. The 150~K system noise temperature is an assumption because no LNB-specific noise-temperature measurement is available for the modeled terminal.
\end{itemize}

\subsection{Computational Methodology}
The project brief used MATLAB's Satellite Link Budget Analyzer as a reference workflow but allowed an equivalent implementation. The calculations were implemented in Python so that the assumptions, equations, test cases, CSV outputs, and plots could be kept in one reproducible codebase. The clear-sky equations follow Pratt's link-budget procedure \cite{pratt}; the additional modules implement the stated ITU-R recommendation versions, a separate illustrative Monte Carlo weather model, interference estimates, dynamic receiver noise, apparent GEO motion, and DVB-S2 ACM.
